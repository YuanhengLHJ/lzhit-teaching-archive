# 业务规则手册（business-rules）

本文件集中沉淀 `lzhit-teaching-archive` 技能的全部业务知识。新增业务知识优先补充到本文件，再由 SKILL.md 与脚本引用。

> ⚠️ 重要原则：**模板可能随学期/学院变化，任何具体模板内容（附件名、材料清单、规范要求）都不得写死进 skill。** 所有规则以"模板目录动态发现 + 归档确认单解析"为准，本文件只描述通用业务逻辑。

---

## 一、补考规则（规则①）

补考**仅适用于理论课（考试）**，即课程类型为 T1 时才涉及补考名单生成。其余课程类型（T2-T5）无补考环节。

### 1.1 补考资格判定

学生具备补考资格，须**同时满足**：

1. **参加了考试**：卷面/考试成绩不为 0，且未被标记为"缺考"。
2. **挂科**：综合成绩（总评）低于 60 分。

### 1.2 无补考资格的情形

- **缺考**考生（考试成绩为 0 且标记"缺考"）：无补考资格。
- 综合成绩 ≥ 60：无需补考。
- 未参加考试但成绩非 0（异常）：标记并提示人工核实。

### 1.3 其他标记的处理

当学生备注/状态栏出现"缺考"以外的标记（如"违纪""免考""缓考""特殊"等）时，**不得自动判定**，须向用户确认该学生是否具有补考资格，并记录确认结果。

### 1.4 补考名单生成

- 仅 T1 课程生成《补考名单》（对应模板 `7.补考/` 目录与各 T1 模板下的"附件9：补考名单"）。
- 补考名单字段：学号、姓名、班级、综合成绩、卷面成绩、补考资格（是/否）、备注。
- 名单生成后须提示用户核实，最终以教务秘书确认为准。

## 二、材料处理边界（规则②③⑤）

技能**不处理**以下材料，须在生成前**明确告知用户不处理范围**，避免用户期望落空。

### 2.1 理论课（考试）T1 —— 不生成下列材料

这些属于"命题/阅卷/考务"环节，由任课教师与教务秘书处理，**不属于技能处理范围**：

| 不生成材料 | 原因 |
|------------|------|
| 命题计划表 | 命题环节，教师填报 |
| A/B 样卷 | 命题环节，教师出题 |
| 答题纸（含封面） | 考务环节，教务秘书处理 |
| 标准答案及评分细则 | 阅卷环节，教师填报 |
| 试卷审批表 | 命题审批环节，教研室/学院签字 |
| 考试资格名单认定及考场签到表 | 考务环节，教务秘书统一打印 |
| 学生答题纸 | 阅卷/归档实物，非生成物 |

> 技能**会处理**的 T1 材料：试卷材料归档目录、过程考核成绩登记表、学生考勤表、成绩登记表、试卷分析报告，以及（若含课内实验）课内实验归档材料。

### 2.2 理论课（考查）T2 —— 《课程考核方案》默认不生成

- T2 的《课程考核方案》（附件1）默认**不生成**。
- 须先**询问用户**是否已有《课程考核方案》：
  - 若用户已有 → 提示用户自行提交，技能不生成。
  - 若用户没有 → 技能为用户生成（基于大纲考核方式与成绩构成）。

### 2.3 任务书 / 实验指导书 / 实训指导书 / 实习指导书 —— 判断教师是否具备

- 这类材料通常在整理教学材料之前，教师就已有成套版本。
- 技能须**根据已有内容判断**教师是否可能具备：
  - 若判断教师**具备** → 提示用户提交原件，技能原样归档（copy）。
  - 若判断教师**不具备** → **询问用户**是否需要技能帮忙生成；用户确认后再生成。

判断依据：用户提供的材料中是否已包含该类文件，或用户在对话中是否提及已有。

## 三、校验依据来源（规则④）

技能的规范性校验**不以硬编码清单为准**，而是动态读取以下两类校验依据：

### 3.1 模板外的"要求及材料提交要求"文件

- 位置：每个课程类型模板目录下，文件名通常含"要求及材料提交要求"（如"！！！！！！（务必仔细阅读）考试要求及材料提交要求.doc"）。
- 作用：该课程类型的整体提交要求与规范说明。
- 处理：若可读取文本（.doc 需转换，.docx 可直接读），纳入校验规则说明；不可读则在报告中注明"要求文件未解析，请人工参照"。

### 3.2 模板内的"归档确认单"

- 位置：每个课程类型模板目录根下，文件名通常含"归档确认单.xlsx"（如"1.（正常班级学生-正考）试卷材料归档确认单.xlsx"）。
- 结构：含"袋内资料"表，列为：序号 | 归档材料 | 规范要求 | 份数 | 自查 | 检查...
- 作用：**这是材料完整性与规范要求的权威清单**。
- 处理：技能解析归档确认单，提取"归档材料"清单与"规范要求"，作为：
  - 材料完整性校验基准（对照清单检查是否齐全）。
  - 规范要求校验基准（对照"规范要求"列检查每项材料是否合规）。

> 归档确认单可能区分"正常班级正考""重修补修正考""补考"等版本，技能按实际场景匹配对应版本。

## 四、模板读取策略（规则⑥ + 总原则）

### 4.1 模板内容不写死

- 任何具体附件名、材料清单、字段都不写进 skill 代码/规则作为硬性常量。
- 所有模板信息通过**运行时动态扫描模板目录**获得（详见 `template-discovery.md`）。
- 学期/学院变更导致模板变化时，只需用户更换模板目录，skill 自动适配，无需改代码。

### 4.2 图片示例不读取

- 模板目录下的图片文件（`.jpg`、`.jpeg`、`.png`、`.gif`、`.bmp`）通常是填报示例/阅卷规范示例，**不读取、不解析**，以节省 token 与处理时间。
- 在归档清单中标注为"图片示例（未解析）"。

### 4.3 临时文件忽略

- `~$` 开头的文件（Office 打开时产生的锁文件）一律忽略。

### 4.4 老格式 .doc 文件

- `.doc`（老格式）python-docx 无法直接读取。技能尝试读取；若失败，在报告中注明"该要求文件为 .doc 格式，未自动解析，请人工参照"，不阻塞流程。

## 五、成绩数据多 Sheet 结构理解

教师提供的成绩数据 xlsx 常为**多 Sheet 结构**，技能须理解各 Sheet 关系，而非只读首个 Sheet。典型结构（以 Python 程序设计 B 为例）：

| Sheet 名 | 内容 | 用途 |
|----------|------|------|
| 成绩总表 | 学号、姓名、平时成绩(课堂表现+平时作业+实验成绩)、考试成绩、最终成绩、及格标志、差异 | 主成绩表，用于归档与补考判定 |
| 考试成绩 | 按题号（一、二、三...）的得分 | 试卷分析依据 |
| 实验报告 | 各实验的报告分 | 课内实验归档 |
| 实验成绩 | 每个实验的操作分+报告分→实验总成绩 | 课内实验归档 |
| 平时作业 | 雨课堂+编程等作业分 | 平时成绩构成 |

处理原则：
- 以"成绩总表"为主表（含最终成绩/综合成绩），用于成绩登记、补考判定、试卷分析。
- "考试成绩"Sheet 用于试卷分析报告的题目维度分析。
- "实验成绩"/"实验报告"Sheet 用于课内实验归档材料。
- 各 Sheet 间以"学号"关联。
- 若数据为单 Sheet，按列名识别（学号、姓名、平时、期末、总评）。

## 六、过程性材料构成分析

过程考核成绩登记表中的过程性材料（平时成绩各分项）**不是固定的**，须**根据大纲分析构成**，再**从教师提供的数据中提取对应分项**，而非简单 dump 全表。

### 6.1 大纲考核构成解析

技能解析大纲的"课程考核与评价"表（表头含"考核方式"+"考核环节"），提取：
- **过程性考核分项**：如课堂表现(10%)、平时作业(10%)、上机操作(20%)。
- **结果性考核分项**：如考试（闭卷）(60%)。
- 每个分项的环节名、权重、评价细则。

实现：`identify_course_type.py:parse_assessment_composition`。仅支持 .docx（直接读表格）；其他格式返回空。

### 6.2 分项与数据匹配

将大纲分项匹配到教师数据中的对应列，匹配顺序：
1. 主表（成绩总表）列名匹配（含同义词）。
2. 其他 sheet 列名匹配。

同义词映射（`build_archive.py:ASSESSMENT_SYNONYMS`）：
- 课堂表现 → 课堂表现 / 考勤 / 课堂
- 平时作业 → 平时作业 / 作业
- 上机操作 → 上机操作 / 上机 / 实验 / 实验成绩
- 实验 → 实验 / 上机
- 课堂讨论 → 课堂讨论 / 讨论 / 互动
- 阶段测试 → 阶段测试 / 测试 / 测验
- 课程报告 → 课程报告 / 报告 / 论文

未匹配的分项须**向用户确认数据列**（不擅自臆测），在日志与校验报告中标注"未匹配分项"。

实现：`build_archive.py:match_assessment_to_data`。

### 6.3 过程考核成绩登记表生成

按大纲分项组织表格（而非简单 dump 全表）：
- 表头：学号 | 姓名 | 各分项(权重) | 过程成绩合计
- 每个分项列从匹配的数据列提取对应学生分数。
- 过程成绩合计 = Σ(分项分数 × 权重)。

实现：`build_archive.py:gen_process_score_sheet`。当材料名含"过程考核""平时成绩""过程性"且已解析到分项时触发此逻辑；否则降级为通用数据表生成。

### 6.4 双行表头数据处理

教师数据的"成绩总表"常为双行表头（第一行分组标题如"平时成绩 40%"，第二行子项如"课堂表现 25%"）。技能合并双行表头时，**第二行非 None 则覆盖第一行**（第二行是更具体的列名），确保子项列名不丢失。

实现：`build_archive.py:read_data_multi_sheet`。

### 6.5 验证示例

Python程序设计B 大纲过程性考核3项：课堂表现(10%)、平时作业(10%)、上机操作(20%)。
数据匹配：课堂表现→成绩总表"课堂表现 25%"列、平时作业→"平时作业 25%"列、上机操作→"实验成绩 40%"列。
生成的过程考核成绩登记表：`学号|姓名|课堂表现(10)|平时作业(10)|上机操作(20)|过程成绩合计`，37名学生数据正确，合计按权重加权（如黄悦：100×10%+78.36×10%+94.2×20%=36.7）。

## 七、分析报告条件生成

分析报告（试卷分析报告/课程考核分析报告/考核分析）的生成有前提条件，**不是无条件生成**。技能以**高校教学专家角度**生成分析报告。

### 7.1 生成前提

须同时满足：
1. **用户数据前提**：用户提供了"试卷""参考答案""考核方案"中的至少一项（作为分析素材）。
2. **模板前提**：模板目录中有分析报告模板（附件名含"分析"）。

### 7.2 三种处理情形

| 情形 | 条件 | 处理 |
|------|------|------|
| 正常生成 | 有素材 + 有 .docx 模板 | 填入模板 + 附加基于成绩与素材的专家分析 |
| 无法编写 | 无素材 | 生成"无法编写_xxx.txt"提示，告知用户需提供试卷/参考答案/考核方案 |
| 模板缺失 | 有素材 + 无模板 | 生成"模板缺失_xxx.txt"提示，告知用户补充分析报告模板 |
| 模板需转换 | 有素材 + 模板为 .doc 老格式 | 生成"待转换_xxx.txt"提示，告知用户转换为 .docx |

### 7.3 素材检测

`detect_analysis_materials(materials_dir)` 扫描用户材料目录，按文件名关键词检测：
- 试卷：文件名含"试卷""样卷"（不含"答案""分析"）
- 参考答案：文件名含"参考答案""答案""评分细则""评分标准"（不含"分析"）
- 考核方案：文件名含"考核方案""课程考核方案"

配置 `materials_dir` 指定材料目录；未指定时默认为数据文件同目录。跳过图片与临时文件。

### 7.4 与教学专家分析报告的区别

- **本节"分析报告"**：填入学校归档模板的试卷分析报告/课程考核分析报告，是**归档材料**的一部分，依赖试卷/参考答案/考核方案。
- **`expert_report.py` 教学专家分析报告**：基于成绩数据的统计分析，独立 md 文件，不依赖试卷素材。
- 两者并存，互不冲突。

实现：`build_archive.py:generate_analysis_report`。

## 八、归档目录填写

归档目录（试卷材料归档目录/考查材料归档目录）可由 skill 帮用户填写。

### 8.1 填写内容

- **课程信息**：填充占位符（开课单位、课程名称、任课教师等，见 `placeholders.md`）。
- **材料清单**：根据实际生成的材料清单（manifest），在"序号|归档材料|份数|备注"表中填写：
  - 序号：自动编号
  - 归档材料：材料名
  - 份数：默认 1
  - 备注：材料状态（已生成/待补充/无法编写等）
- 跳过合并单元格的只读单元格（MergedCell），避免写入异常。

### 8.2 模板发现

- 归档目录模板在模板目录的附件中（文件名含"归档目录"，扩展名 .xlsx）。
- `build_archive.py` 动态发现归档目录模板（不依赖 DEFAULT_CONVENTION 是否列出）。
- 若循环中已生成归档目录（DEFAULT_CONVENTION 列出），跳过动态发现；否则循环后动态发现并填写。

### 8.3 实现

`fill_archive_directory(template_path, dst, manifest, course, values)`：读取归档目录模板 → 填充课程信息占位符（跳过 MergedCell）→ 找"序号+材料名称/归档材料"表头行 → 在其后填写材料清单 → 追加 AI 附注。

### 8.4 验证示例

Python程序设计B（T1）归档目录填写 16 项材料（教学大纲、教学日历、期末试卷A/B、参考答案、命题审批表、试卷分析报告等），份数默认 1，合并单元格（标题行、填表说明）被跳过未出错。

## 九、规则补充机制

本文件为业务知识的**单一事实来源**。后续补充业务知识时：

1. 优先新增到本文件对应小节。
2. 若涉及新课程类型的特殊规则，在对应小节下增列。
3. 若涉及校验规则细化，同步更新 `validation-rules.md` 并引用本文件。
4. 脚本读取本文件规则时，保持"规则优先于代码"原则——规则变更尽量只改 md，不改代码。
